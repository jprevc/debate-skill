# Spec: `/debate` skill

Status: ready-for-agent

Vocabulary follows `GLOSSARY.md`. See `docs/adr/0001-verdict-free-report.md`.

## Purpose

Help the user decide on a binary **Motion** (political, technical, scientific or personal), and argue either **Side** of it, by running a structured debate between opposing **Advocates**. Every **Claim** is traceable to recorded **Evidence**, and everything ends in a verdict-free **Report**.

Typical uses: deciding how to vote on a bill or referendum, settling a disputed question, preparing counter-arguments against opponents.

## Packaging

- This repo is the skill directory. It contains only skill files (plus dev docs: `CLAUDE.md`, `GLOSSARY.md`, `docs/`, `.scratch/`).
- Install by symlinking it: `ln -s ~/Sync/debate ~/.claude/skills/debate`.
- Invocation: `/debate <motion text | link | question> [quick] [--dir <path>]`.
- Layout:

```
SKILL.md                 orchestration protocol (main agent)
prompts/advocate.md      brief for Advocates (Opening Case, Rebuttal, Rejoinder)
prompts/auditor.md       brief for Auditors
prompts/judge.md         brief for the Judge
reference/evidence.md    shared rules: Evidence, IDs, Source Tiers, Claims, responses, Evidence Requests
scripts/ledger.py        rebuilds ledger.md; flags dangling and uncited Evidence
scripts/evidence.py      fetch / search / show / quote / verify sources without loading whole pages into context
templates/state.md
templates/motion.md
templates/evidence.md
templates/case.md        shared by Opening Case / Rebuttal / Rejoinder outputs
templates/audit-batch.md
templates/report.md
```

Write the prompt files following the `writing-for-agents` skill.

## Debate folder

Each debate is stored in `<root>/<YYYY-MM-DD>-<motion-slug>/`, where `<root>` is the directory `/debate` was invoked from, or the one given with `--dir`. It is never stored inside the skill directory.

```
state.md                 stage status, mode, Dimensions, Advocate groups, open Evidence Requests
motion.md                Motion, scope, Primary Text reference, Dimensions, Source Tier definitions for this domain, arguments the user has heard
ledger.md                index of all Evidence (regenerated by main agent between Stages)
evidence/E-<SIDE>[-<GROUP>]-<NNN>.md
evidence/files/          files supplied by the user
notes-pro.md, notes-con.md   Advocate research memory (leads tried, dead ends, planned attacks)
1-opening-pro.md, 1-opening-con.md
2-rebuttal-pro.md, 2-rebuttal-con.md
3-audit.md               (merged; batch outputs as 3-audit-batch-<N>.md)
4-rejoinder-pro.md, 4-rejoinder-con.md
report.md
```

When a Side has multiple Advocate groups (see Scaling), the case files get the group suffix as well, e.g. `1-opening-pro-A.md`.

## Resumability

- Resuming works at Stage granularity. Every Stage reads all its inputs from files and writes all its outputs to files. A fresh session can continue from `state.md` alone.
- Every subagent is spawned fresh for every Stage. An Advocate's continuity comes from its notes file, not from conversation memory.
- If `/debate` is invoked in a folder that already has a `state.md` (or one is given with `--dir`), resume at the first Stage not marked done. A Stage that was interrupted part-way is rerun from scratch. Its partial outputs are overwritten, but Evidence files that were already written and are cited elsewhere are kept.

## Stages

### 0. Framing (main agent + user)

1. Turn the user's input into a binary Motion. If the input is an open question, propose a Motion and confirm it with the user.
2. If the Motion has no factual content (pure taste or value), warn the user and offer to stop.
3. Ask only scope questions: what exactly the Motion is, jurisdiction or context, the decision or vote date, links the user already has, and arguments the user has heard and wants addressed. **Never ask about the user's leanings or values** (ADR 0001).
4. If a Primary Text exists, fetch it and record it as `E-PRIMARY-001`. If the main agent can't fetch it, raise an Evidence Request.
5. Propose the Dimensions (provisions of a document, or cross-cutting themes) and let the user confirm or edit them.
6. Write the Source Tier definitions for this domain into `motion.md`.
7. Create the debate folder, `state.md` and `motion.md`.

### 1. Opening Case (Advocates, parallel)

Each Advocate builds the strongest Evidence-backed case for its Side across all Dimensions (or across its group of Dimensions). It must address every argument from the "arguments the user has heard" list that bears on its Side. It may propose new Dimensions. The main agent adds accepted ones to `state.md`, and the other Side must address them in its Rebuttal.

### 2. Rebuttal (Advocates, parallel)

Each Advocate receives `motion.md`, the opponent's Opening Case, `ledger.md`, its own notes file, and its own Opening Case. It must respond to **every** opposing Claim, organized by Dimension, in exactly one of three ways:

- **Rebut**: counter-Evidence, or a flaw in the opposing Evidence.
- **Mitigate**: accept the Claim but argue it matters less, with reasoning or Evidence.
- **Concede**: explicitly state that it cannot counter the Claim.

Ignoring an opposing Claim is not allowed.

### 3. Evidence Audit (Auditors, parallel batches)

- The main agent splits all Evidence into batches of about 20 and spawns one fresh Auditor per batch. A final merge step writes `3-audit.md`.
- **All** Evidence is audited. There is no sampling.
- For each Evidence the Auditor:
  - re-opens the source and confirms the verbatim quote exists;
  - checks that the quote, in its context, supports each Claim that cites it, flagging cherry-picking;
  - assigns a Source Tier and, for tier C, records who funds or runs the source;
  - fills in the audit fields in the Evidence file.
- Auditors are neutral. They don't know which Side "should" win and don't weigh the arguments.
- A user-supplied file is audited against `evidence/files/`.

### 4. Rejoinder (Advocates, parallel; skipped in `quick` mode)

Each Advocate answers the Rebuttal against it. It may rely only on Evidence that survived the Audit plus new Evidence (which is audited in a short follow-up batch before Judgment). It also must say how it handles any of its own Evidence that failed the Audit: drop, replace or downgrade the Claim.

### 5. Judgment (Judge)

A fresh Judge reads only the debate folder. It never sees the Framing conversation. It writes `report.md` (see Report).

### Between Stages (main agent)

1. Regenerate `ledger.md`.
2. Update `state.md`.
3. Collect the **Evidence Requests** from the Stage outputs and ask the user for them, critical ones first.
4. Store whatever the user supplies as `E-USER-<NNN>` (files go in `evidence/files/`) and mark the matching **Pending Evidence** Claims as fulfilled.
5. Leave anything the user can't supply as Pending Evidence. The Report shows it as unsupported.
6. Ask the user for nothing else: no leanings, no opinions.

## Evidence

One file per Evidence, `evidence/<ID>.md`. IDs never change once assigned.

ID prefixes:

- `E-PRIMARY-` for the Primary Text
- `E-PRO-` and `E-CON-` for Advocates
- `E-USER-` for anything the user supplies

With multiple Advocate groups, IDs add the group, e.g. `E-PRO-A-004`.

Fields:

- ID, added by (Side/group or user), Stage added
- URL (or `evidence/files/...` path), access date
- title, author, publisher, publication date
- verbatim quote in the original language
- translation, if the quote is not in the Report's language
- surrounding context: about one paragraph before and after the quote
- audit, filled in by the Auditor:
  - quote found: yes / no / partially
  - supports the Claims: yes / partly / no, per Claim
  - cherry-picking flag
  - Source Tier
  - funder or affiliation (tier C)
  - Auditor notes

### Rules

- Every Evidence must be cited by at least one Claim. Material collected "just in case" isn't allowed.
- There are no caps on the amount of Evidence.
- Which Claims cite an Evidence is derived from the case files by `scripts/ledger.py` into `ledger.md`, not stored in Evidence files; this lets parallel Advocates cite each other's Evidence without editing the same file.
- Never cite from memory. If a source can't be reached (paywall, offline, must be requested from an institution), raise an Evidence Request instead.
- Sources may be in any language. The quote is always stored in the original language.

### Source Tiers

Tiers are defined by the source's independence. `motion.md` gives domain-specific examples.

- **A**: primary or authoritative. The Primary Text, official statistics, court rulings, peer-reviewed research.
- **B**: independent expert sources, such as fiscal councils, courts of audit, international bodies and quality journalism.
- **C**: interested parties, such as advocacy groups, think tanks, parties, campaigns and vendors. Their funder or affiliation must be recorded.
- **D**: opinion, such as op-eds, blogs and social media. Valid only as Evidence of what someone said, never of a fact.

## Claims

Every Claim has an ID (`PRO-7`, `CON-3`, or `PRO-A-7` with groups), a Dimension, a type, and its cited Evidence IDs.

| Type | Requirement |
|---|---|
| Factual | must cite Evidence |
| Predictive | must cite Evidence for the mechanism or for comparable cases |
| Value | no Evidence needed; labeled as a value |
| Inference | shows its reasoning from the Evidence it cites |

- A Claim that depends on an open Evidence Request is marked Pending Evidence.
- Advocates argue one-sidedly but must never fabricate, misquote, or present unsupported Claims as fact.

## Evidence Requests

Each request is written in the Stage output. It contains:

- an ID
- the dependent Claim IDs
- what is needed, and why the Advocate can't get it itself
- where the user could get it
- priority: `critical` or `nice-to-have`

## Scaling

- The default is one Advocate per Side.
- When there are more than about 6 Dimensions, the main agent splits the Dimensions into groups and spawns one Advocate per Side per group. Groups are recorded in `state.md`.
- Each group has its own notes file (`notes-pro-A.md`) and its own case files (`1-opening-pro-A.md`).
- In the Rebuttal, each group answers the opposing group that covers the same Dimensions.

## Modes

- **full** (default): all Stages.
- **quick**: skips the Rejoinder. It does not limit Evidence or the Audit.

## Report

`report.md` is written in the language of the user's prompt. Evidence IDs are relative links to `evidence/<ID>.md`. Sections:

1. **Motion and scope**: what was debated, the Primary Text, the Dimensions.
2. **Bottom line by Dimension**:
   - **Settled facts**: conceded Claims, and Claims with tier A/B Evidence that survived the Audit.
   - **Factual Cruxes**: settled one way, or shown to be unsettled by the Evidence.
   - **Value Cruxes**: framed as "if you weigh X over Y, the Evidence favors <Side>".
3. **Strength of each case**: an honest statement of any imbalance, covering the Source Tier distribution, failed Audits, how much each Side rests on Value Claims, and Pending Evidence. No false balance (ADR 0001).
4. **Cheat Sheet for each Side**: the arguments opponents are likely to raise, the best Evidence-backed counters, and which points to concede because they are true.
5. **Unresolved**: open Evidence Requests and unsettled Factual Cruxes.
6. **Evidence index**: link to `ledger.md`.

The Report **never** recommends a vote or declares a winner.

## Test Motions

Use one Motion of each kind to validate the skill:

- political, a bill with a Primary Text and several Dimensions (ideally a Slovenian one, to test non-English sources)
- technical, e.g. "Our team should migrate from REST to GraphQL"
- health or science, e.g. "Intermittent fasting improves long-term weight loss more than calorie restriction"
- personal, with critical Evidence Requests, e.g. "I should accept job offer X"

Check that:

- a fresh session can resume from the end of each Stage;
- every Claim in the Report traces back to Evidence that survived the Audit;
- no participant other than the main agent ever sees the user's Framing conversation.
